## 現在の進め方

Puttの完全完成をAdSense審査の前提にはしません。
Multicolor Sweeperを審査の主力とし、Puttは「通常ツアーが開始から終了まで安定して遊べる状態」で掲載できるようにすることを優先します。

Putt側の当面の順序は次のとおりです。

1. **試遊フィードバックと今後の方針を記録する**（この文書）
2. **審査掲載前に必要な導線を整える**
   - ゲーム内から `https://hanage.app/privacy/` を開ける
   - 簡単な遊び方をトップから確認できる
   - 未接続の週替わりチャレンジは、審査時に「準備中」を目立たせないため公開トップから一旦隠す
3. **遊びに直接支障する小さな分かりにくさだけ先に直す**
   - OB境界が分かりづらく、通常プレイの失敗原因になる場合は視認性を改善する
4. **公開URL・ハブ導線・主要端末を確認し、AdSense審査へ進む**
   - AdSense申請そのものとハブ全体の準備は `hanage-hub` 側の計画を正とする
5. **審査を待たせない改善は後続で進める**
   - 固定ホールの再選定
   - コース生成器v2
   - 練習グリーン専用化
   - パター感度とグラフィック
   - 転がりスキップ
   - 週替わりチャレンジ、ランキング、広告統合

以下の改善事項は、現在の通常ツアーが破綻なく遊べる限り、AdSense審査開始のブロッカーにはしません。

## 1. 固定ツアー / コース生成

### 実機で気になった点

- **風の丘 H5 / H6 / H7 が似た印象で続き、変化が少なくつまらない**
  - H5: seed 798
  - H6: seed 354
  - H7: seed 977
- 風の丘は現在、後半にストレート系が多く、9ホールを通したときの変化が弱い
- ドッグレッグが全体的に**直角に近い折れ方**に見え、不自然
- S字も「自然に曲がるコース」というより、折れ線を二度曲げた人工的な形に見える

### 面白いと感じた基準ホール

今後の再選定・生成器改善では、以下を「このゲームで面白いと感じた例」として比較基準にする。

- **曲がりの森 H8** — seed 649
- **水鏡の庭 H1** — seed 394
- **水鏡の庭 H4** — seed 235
- **水鏡の庭 H7** — seed 411
- **水鏡の庭 H8** — seed 421

数値指標だけで候補を選ばず、「どこへ打つかを考える余地」「見た目の変化」「池や曲がりの効き方」を人の試遊で確認する。

### 現行生成器で起きやすい理由

現在のルートは `straight / dogleg / doubleDogleg` の折れ線として作られる。
特に難しいホールの `cornerAngle` は 60〜105° の範囲なので、ドッグレッグが90°前後へ寄りやすい。
S字も二回の折れで作るため、連続した自然なカーブになりにくい。

また、固定ツアーの選定はホール単体のPAR・地形・池・遠回り率などを重視しており、**前後のホールとの似方**を十分に評価していない。
今後は「良いホールを9本集める」だけでなく、9ホールを通した並びの多様性も評価する。

### 先にできる小さい対応

生成器を変えなくても、固定ツアーだけならシードの差し替え・並べ替えで改善できる。
特に風の丘 H5〜H7 は、候補を再試遊して連続する形・距離・地形が似すぎない構成へ変更する候補とする。

ただし固定シードを変更すると、そのコースの古いラウンド進行は `RoundProgressStore` のシード列照合で破棄される。
また週替わり候補との重複検証も必ず再実行する。

### 将来のコース生成器v2

**現行生成器を直接別物へ上書きしない。**
固定シード、週替わりチャレンジv1、過去の検証結果を再現できるよう、現在の生成方式をv1として残し、新しい方式はv2として追加する。

v2で検討すること:

- ドッグレッグを一つの鋭い角ではなく、複数の制御点や曲線で自然に曲げる
- S字も二つの角ではなく、緩い連続カーブとして作る
- 「難しい = 曲がり角が大きい」への依存を減らす
  - 芝幅
  - 池の位置
  - 傾斜
  - 安全ルートと近道の選択
  などでも難易度を作る
- 曲がり角度の分布を見直し、90°前後ばかりにならないようにする
- 9ホールを組むときに、形・距離・池・地形の連続重複を避ける指標を追加する
- 上記「面白いと感じた基準ホール」を壊さない方向か、実機で比較する

## 2. 練習モードを「練習グリーン」らしくする

### 実機での案

現在の練習は通常コースと同じ生成器の1ホールを繰り返す形だが、将来は本コースとは見た目から分かる**専用の練習グリーン**にしたい。

方向性:

- 背景を本コースほど山がちにしない
- 外形を自然地形ではなく、管理された施設らしい少し人工的な形にする
- 全体は比較的平らめにする
- 木や大きなハザードを減らし、パッティング練習に集中できる見た目にする
- 本コースの生成器を無理に流用せず、必要なら練習専用定義・専用生成処理を持つ

これは通常ツアーを遊べるようにする作業より後でよく、AdSense審査のブロッカーにはしない。

## 3. パターの操作感

### 症状

実機では「パターの挙動が少し敏感すぎる」感触がある。
ただし、何が敏感なのかを一つに決めつけず、次の要素を分けて確認する。

- **実際の打ち出し方向**の感度
- **強さ**（`speedK` / パター強さ倍率）の感度
- **画面上のパターフェース表示**の角度感度・追従

現在、画面上のフェース角にはゲーム本体用の感度・平滑化が入っている一方、実際の打ち出し方向は別の計測値を使う。
見た目だけを鈍らせて解決したように見せないこと。

改善時は一度に複数の感度を変えず、 `/swipe-test/` とゲーム本体を使って原因を切り分ける。

## 4. パターヘッドのグラフィック

現在のパターヘッドは2D Canvas上のほぼ長方形で、道具というより図形に見える。

将来は、計測ロジックや当たり判定を変えずに、**ゴルフのパターヘッドと分かるシルエット**へ変更する。
リアルな3Dモデルを目標にはせず、ブレード型または簡素なマレット型など、このゲームの簡素なグラフィックに合う表現でよい。

AdSense審査のブロッカーにはしない。

## 5. OB境界の視認性

### 症状

プレイ中、どこからOBなのかが直感的に分かりづらいことがある。
これは単なる見た目ではなく、プレイヤーが安全な打ち先を判断できるかに関わるため、他の改善より優先度を上げてもよい。

候補:

- OB側に白杭などの境界マーカーを置く
- セカンドカットとOBの色・質感差を少し強くする
- コースマップでも境界が読み取りやすいか確認する

実装前に、通常画面・コースマップの両方で邪魔にならない最小の表現を選ぶ。
審査前の実機確認で「普通に遊ぶうえで迷う」状態が続くなら、審査前の小修正として扱う。

## 6. ボール走行のスキップ

長いショットでは、結果が決まるまで転がりを見続ける時間が長い。
将来は、ボールが転がっている間にタップすると結果まで進められるようにする。

方針候補:

- タップ後も**同じ固定タイムステップの物理を内部で進め、結果そのものは変えない**
- 位置を近似してテレポートさせたり、別の簡易計算へ切り替えたりしない
- スキップ後は通常どおりRESULTへ入る
- 「走行中に俯瞰へ切り替えない」という既存原則は維持し、途中の分析画面にはしない

操作感を変えるため実機確認が必要。審査後の改善でよい。

## 優先度まとめ

| 項目 | 審査前 | その後の優先度 | 備考 |
|---|---|---|---|
| プライバシー導線 | 必須 | — | `hanage.app/privacy/` へ |
| 簡単な遊び方 | 必須 | — | トップから確認可能にする |
| 未完成「週替わり」の公開トップ表示 | 非表示化 | 後で接続 | 準備中表示を審査時に残さない |
| OB境界 | 条件付きで先行 | 高 | 通常プレイに支障するなら審査前 |
| 固定ホールの差し替え・並び | ブロッカーにしない | 高 | 風H5〜H7を重点確認 |
| コース生成器v2 | 不要 | 高 | v1を保存して別方式にする |
| 練習グリーン専用化 | 不要 | 中 | 通常ツアーと見た目を分ける |
| パター感度 | 不要 | 高 | 原因を分解して調整 |
| パターヘッド | 不要 | 中 | 当たり判定とは分離 |
| 転がりスキップ | 不要 | 中 | 結果の決定論を維持 |
| 週替わり / ランキング / 広告統合 | 不要 | 初回完成には必要 | AdSense審査開始を待たせない |
