### 現行生成器で起きやすい理由

現在のルートは `straight / dogleg / doubleDogleg` の折れ線として作られる。

今後は「良いホールを9本集める」だけでなく、9ホールを通した並びの多様性も評価する。

### 生成器v2 第1段階の実装（2026-09-15・**実機確認待ち**）

設計の正本は `docs/course-generator-v2.md`、数字は `PROJECT_STATUS.md` の「生成器v2の実測」。
ここには**実機で決めてもらうこと**だけを書く。

v1は一切触っていない（シード1〜200でサーフェスのダイジェストとハイトマップが完全一致することを確認済み）。
v2は `?gen=v2&seed=N` で1ホールずつ出せるので、**同じシードでv1とv2を交互に見比べられる。**

#### 実機で見てほしいところ

1. 曲がりが「折れ」ではなく「カーブ」に見えるか
2. S字が自然な蛇行に見えるか
3. 難しさが角度以外（芝幅・池・傾斜・近道の選択）から来ていると感じるか
4. **v1のコースと並べたとき、v2のほうが面白いか。同等なら採らない**

基準ホール（曲がりの森H8=649、水鏡の庭H1=394 / H4=235 / H7=411 / H8=421）は
v1のまま残っているので、`?seed=649` と `?gen=v2&seed=649` を並べて見られる。

#### 数字の上では直ったが、実機で確かめる必要があること

- **「回り込む」感じが薄くなっていないか。**
  遠回り率の中央値は v1 1.12 → v2 1.02、最大は 1.64 → 1.20 に下がった。
  これは幾何の帰結で、曲率半径に下限を設ければ同じ全長で曲がれる量は必ず減る。
  数字の上での症状（折れ角が90°前後に固まる）は消えたが、
  **代わりにコース全体が素直になりすぎていないか**は人が見るしかない。
  薄いと感じたら効かせる順は次のとおり
  1. `CONFIG.course.generatorV2.curve.minTurnRadiusWidthFactor` を下げる（曲がれる量が増える）
  2. 同 `turnSpread` の下限を下げる（真っ直ぐな区間を長く取り、曲がりを一箇所へ寄せる）
  3. 難易度ごとの `routeLength` を伸ばす（長いほど大きく曲がれる）
- **高さのハザードが効いているか、邪魔なだけか。**
  勾配の上限は5%に抑えてある（摩擦に負ける勾配は7.8%）。
  芝の上で摩擦に負ける面の割合は v1 2.18% → v2 1.94% なので、
  「転がり続ける」は増えていない。逆に**薄すぎて分からない**可能性のほうが高い
#### 実機で出た判断（2026-09-15）

- **深いラフの島は不採用。** 「コースの真ん中にある濃い緑はいらない。
  ただのラフが真ん中にあるのと同じで、ただ邪魔なだけ」。**コードごと削除した。**
  数えたら87%が中心線を塞いでいて、逃げ道が無く選択になっていなかった
  （詳細は `PROJECT_STATUS.md`）
- **代わりにバンカーを入れた。** 「バンカーはなんでない？」を受けて同じセッションで実装。
  砂は越えられるので線の上に置けて、**必ず反対側に通れる芝を残す**ので
  「強く越えるか、避けて回すか」の選択になる

#### 1回目の実機確認で出た指摘と、その対応（2026-09-15）

**砂の色（`0xd8c48a`）はOK。** それ以外は指摘どおり直した。

| 指摘 | 対応 | 実測（前 → 後） |
|---|---|---|
| ホールの前半には置かないでほしい | `routeRange` を [0.2,0.8] → **[0.5,0.85]** | 前半に出る割合 90% → 3% |
| 面積を平均4割くらい下げたい | 半径 1.1〜2.1 → **1.1〜2.0**、置ける範囲も狭めた | 面積比 2.12% → **1.17%（-45%）** |
| フェアウェイへのはみ出しも同じくらい小さく | `maxCenterOverlap`（中心線を越えてよい量）を新設 | 食い込み 最大1.42m → **0.46m** |
| ゆるいすり鉢状に窪んでいるのが自然 | バンカーごとに窪みの高さハザードを足した | 勾配 8%。**縁で傾きが0**なので芝側に斜面が出ない |
| 丸っぽい形ばかり。細長い／ひょうたん型も | `hazardShape` を新設（**池とバンカー共通**） | ひょうたん 7〜9% / 細長 7〜14% |
| 尾根・窪地の実感がない | 勾配の上限 5% → **7%**、尾根をルート上へ寄せた | 高低差 平均9.2→**12.6cm** / 最大14.2→**19.7cm** |

**「実感がない」は事実だった。** 勾配の上限5%だと、この形の高さは
「勾配 × 短いほうの半径 ÷ 1.54」で最大14cmにしかならず、
**既存のうねり（±20cm）に埋もれていた。** 芝で止まれる勾配が7.84%なので7%が天井で、
これ以上は「下りで止まらない斜面」が増えるため上げられない。
あわせて、尾根がルート脇にも置かれていて「越える対象」になっていなかったのを、
線の上へ寄せた（`ridgeOffset`）。

#### 2回目の実機で見てほしいところ

1. **尾根・窪地が読めるようになったか。** まだ足りなければ、次に効かせられるのは
   半径を広げること（勾配は据え置きで高さだけ上がる）だけ。勾配はもう上げられない
2. バンカーのすり鉢が「自然な窪み」に見えるか。深すぎ／浅すぎないか
3. ひょうたん型・細長い形の出る頻度（1割弱）が適当か。もっと欲しいか
4. バンカーが後半だけになったことで、ホールの組み立てが単調になっていないか
5. 砂に入ったとき、次の一打の短さ（摩擦はセカンドカットの8倍）が「罰」として伝わるか。
   **罰打は無い**ので、伝わらなければただ止まるだけの地面になる

## 2. 練習モードを「練習グリーン」らしくする

### 実機での案

現在の練習は通常コースと同じ生成器の1ホールを繰り返す形だが、将来は本コースとは見た目から分かる**専用の練習グリーン**にしたい。

方向性:

- 背景を本コースほど山がちにしない
- 外形を自然地形ではなく、管理された施設らしい少し人工的な形にする
- 全体は比較的平らめにする
- 木や大きなハザードを減らし、パッティング練習に集中できる見た目にする
- 本コースの生成器を無理に流用せず、必要なら練習専用定義・専用生成処理を持つ

これは通常ツアーを遊べるようにする作業より後でよく、AdSense審査のブロッカーにはしない。

## 3. パターの操作感

### 症状

実機では「パターの挙動が少し敏感すぎる」感触がある。
ただし、何が敏感なのかを一つに決めつけず、次の要素を分けて確認する。

- **実際の打ち出し方向**の感度
- **強さ**（`speedK` / パター強さ倍率）の感度
- **画面上のパターフェース表示**の角度感度・追従

現在、画面上のフェース角にはゲーム本体用の感度・平滑化が入っている一方、実際の打ち出し方向は別の計測値を使う。
見た目だけを鈍らせて解決したように見せないこと。

改善時は一度に複数の感度を変えず、 `/swipe-test/` とゲーム本体を使って原因を切り分ける。

## 7. 進行表示（何ホール目・何打目）が読み取りにくい（新規・2026-09-13）

**修正済み・実機確認待ち。**

### 症状

プレイ中に「今が何打目か」がすぐ分からない。何ホール目かも含めて把握しづらい。

### 現状の実装

HUDは1行だけで、すべて同じ大きさの等幅で並んでいる（`progressText()` / `src/i18n.ts`）。

```
HOLE 3/9  PAR 4  2打 +1  3.42m
```

- 5つの数字が同じ重みで並ぶため、視線が「今の打数」へ行かない
- 打数とパー差（`2打 +1`）が隣り合っていて、どちらが打数か一瞬迷う
- 折り返しを避けるため区切りは空白だけ。区切りとしても弱い
- カード表示中はHUDごと引っ込む（`quiet`）ので、ホール番号を確認する場所が無い瞬間がある

### 参考にした中継の整理

ゴルフ中継は同じ項目でも「常時／局面／節目」で出し方を変えている。

| 項目 | 中継での出し方 | いつ |
|---|---|---|
| 通算パー差 | `-3` / `E` / `+2`。**アンダーは赤、オーバーは青か黒**。記号も併記 | 常時・一番大きい |
| 消化ホール | `THRU 15` | 常時・小さい |
| ホール番号・PAR・距離 | `18H PAR5 542Y` をコース俯瞰と一緒に | 入り口で一度だけ・大きい |
| 何打目か | 「第2打」 | そのショットの前後・小さい |
| 残り距離 | 「ピンまで3.2m」 | 打つ前後 |
| スコア確定 | 「バーディ」＋赤丸 | カップインの瞬間・一瞬 |

参考にするのは**情報の並べ方と優先度**であって、中継画面の意匠ではない。

### 修正

中継のホール表示を左端に置き、その右へ3つの読み取りを同じ大きさで並べた。

```
[ 2 ][ 20m ]  SHOT 1  TOTAL +3  TO PIN 20.31m
     [PAR 4]
```

- **ホール表示**: 白地に反転したホール番号＋全長／PARの2段。2段でも1行ぶん（22px）に収める。
  練習ではホール番号を出さず枠を閉じる
- **全長**はティー→カップの直線ではなく、遊べる芝の中心線（`route`）に沿った長さ。
  実際のゴルフのヤード表記と同じで、**ティーからの残り距離とは一致しない**
  （ストレートでもルートは弓なりなので、9.02m のホールが 9m と出る）。
  中継のヤード表記に合わせて整数で出し、小数2桁の残り距離と桁を揃えない。
  ホール入り口の紹介も同じ数字にした
- **打数**は「打った数」ではなく「今どの一打か」（中継の「第2打」と同じ数え方）。
  構えている間はこれから打つ一打、転がってから停止までは今打った一打
- **通算パー差**は打数の隣だと「このホールで+1」と読まれるので `TOTAL` の語を付ける。
  中継の規約に合わせてアンダーは赤、オーバーは青。`+` `-` の記号も残す
- **残り距離**は `TO PIN` を付ける（中継の「152 YDS TO PIN」と同じ言い方。
  `LEFT` は会話では使うが表示の語ではない）。転がっている間も出し続ける
  （ピンを越えたかの判断に使うため。これは変えない）
- 帯の中の語は**日本語でも英語のまま**（`SHOT` / `TOTAL` / `TO PIN` / `PAR`）。
  中継と同じ短い語で通じ、幅も言語で変わらない。
  パー差のイーブンは英語表記の `E`（カードの中は日本語に合わせて `±0` のまま）
- ホールの入り口に `HOLE 3` / `PAR 4・12.4m` を一度だけ大きく出す（中継のホール紹介）。
  時間は `src/config.ts` の `round.holeIntro`。**ツアーだけ**
- 狭い画面では従属側の文字と間隔だけを1段落とし、右上のボタンに当たらないようにした

**帯の高さは55pxのまま変わっていない**（320 / 360 / 390px、練習・ツアーで実測）。

### ホール終了・ラウンド終了のカードも同じ組み方にした（2026-09-14）

試遊で「ホール終わりの表示が微妙」と出たので、HUDと同じ考え方へ揃えた。

```
   HOLE 5 / 9   PAR 4         ← PARはそのホールの素性なので上に置く
   DOUBLE BOGEY               ← 主役。中継と同じで、スコアはまず語で言う
   6 STROKES                  ← 語がスコアの意味を、こちらが実数を言う
   ᵀᴼᵀᴬᴸ +1    ˢᵀᴿᴼᴷᴱˢ 19     ← ラウンドの成績。HUDと同じ組み方で2欄に分ける
```

**`TOTAL` はパー差、打数の合計は `STROKES`。** 英語のリーダーボードでは
`TOTAL` の列に入るのはパー差（`-12` など）で、打数の合計は別列の `STROKES`（`TOT`）。
取り違えると意味が逆になる。

- 判定語は `HOLE IN ONE` / `ALBATROSS` / `EAGLE` / `BIRDIE` / `PAR` / `BOGEY` /
  `DOUBLE BOGEY` / `TRIPLE BOGEY`。+4以上と−4以下は英語圏でも語で言わないので数字のまま。
  ギブアップは `GAVE UP`
- ラウンド終了は判定語が無いので、中継のリーダーボードと同じく**通算パー差を主役**にし、
  下に合計打数（`40 STROKES`）、その下に `HOLES 9` `PAR 36` を並べる
- パー差の書き方をゲーム中で1つにした。イーブンは `±0` → **`E`**（英語のゴルフ表記）。
  スコア表と自己ベストの表示も同じ書き方になる
- 色は中継の規約どおり、アンダーは赤、パーは白、ボギー以上は青

### ついでに直した不具合（2026-09-14）

カードに出ていた**中身が空の黄色い箱**は、自己ベストの表示（`#tour-best-result`）だった。
`entry.ts` が id セレクタで `display: inline-block` を当てており、**`hidden` 属性が効いていなかった**。

- 自己ベストが無いラウンドでは空の箱がカードに残る
- 一度ラウンド終了でベストを出すと、その後のホール間のカードにも出続ける

`#tour-best-result[hidden] { display: none; }` を足して閉じた。

### 試遊で出た直し（2026-09-14）

- **練習のカードから「練習終了」の文言を外した。** カード自体は残し、見出しは `PAR 4` だけにした。
  カードの構成と操作は変えていない
- **ホール紹介を画面の中ほどへ移した。** 上に出ると旗竿と重なって一瞬でも邪魔だった。
  出るときはカメラの切り替わりと同時にフェードなしでパッと出し、消えるときだけフェードさせる
  （0.5 → 0.25秒）
- **ストローク中に画面の左端までスワイプすると、ブラウザの「戻る」が発動することがあった。**
  iOS Safari の端スワイプは `touch-action: none` では止まらず、`touchstart` を
  打ち消したときだけ止まる（ポインターイベントでは効かない）。
  左右端から始まった指だけ打ち消すようにした。幅は `src/config.ts` の `game.edgeSwipeGuard`

### 残りの確認

可読性の問題なので、実機で「一目で読めるか」を確認して採否を決める。

- ホール表示の全長・PARの文字（9px）が実機で読めるか
- 打数・通算・残りの大きさ（14px）が適切か
- 通算の赤・青が暗い緑の帯の上で読めるか
- ホール紹介の2秒（`round.holeIntro.duration`）が長すぎないか、位置が邪魔にならないか
- カードの判定語（32px）とその下の打数（18px）の釣り合い
- イーブンの `E` が日本語版でも読み取れるか（`±0` に戻すなら `i18n.formatDiff` の1箇所）
- 端スワイプの抑止が実機で効くか。止める幅（28px）が広すぎて端の操作を邪魔しないか
- 練習のカードの見出しが `PAR 4` だけになっているか（自動操作ではパットを沈められず未確認）

## 8. カップイン直後にカードが出てラインを確認できない（新規・2026-09-13）

**修正済み・実機確認待ち。**

### 症状

カップインした直後にオーバーレイ（ホールアウトのカード）が出るため、最後の一打のラインが見えない。

### 現状の実装

停止 → 俯瞰への遷移 → カードの順で、時間はすべて `src/config.ts` にある。

- `result.settleDelay` = 0.35s（停止から遷移開始まで）
- `result.transition` = 1.8s（俯瞰への**カメラ遷移そのもの**の長さ）
- `round.cardDelay` = 0.8s（`resultReady` になってからカードまで）

`cardDelay` は遷移の**開始**から数えているので、カードは停止の約1.15秒後に出る。
一方で俯瞰への遷移は1.8秒かかる。**カメラが俯瞰へ着く前にカードが重なる**ため、
軌跡を出した意味がほとんど無くなっている。

### 修正

- `cardDelay` を俯瞰への遷移が終わってから数え始めるようにした。
  カードが出るのは停止から `settleDelay` + `transition` + `cardDelay` = 約2.95秒後になる
- 待ちきれないときは、従来どおり画面タップでカードを早出しできる
- 値そのもの（0.8秒）と物理・罰打計算は変更していない

俯瞰へ着いてからラインを読む間があるか、逆に長すぎないかを実機で確認する。
長さを変える場合は `src/config.ts` の `round.cardDelay` だけで調整できる。

### 残りの確認

- 軌跡を見る時間を何秒取るかは実機で決める（今は0.8秒）
- 「タップで初めてカードを出す」案もあるが、今はカード自体がタップで進むので操作が二重になる。
  自動で出すなら十分待つ、待たせないならタップ、のどちらかに寄せる
- ホールアウト以外の一打（`noticeNextPutt`）は今までどおりで良いか、あわせて確認する

## 9. ホールアウトのジングルが浮く（新規・2026-09-13）

### 症状

ホール間に鳴るジングルが、ゲームの音の中で浮いて聞こえる。もっと静かにしたい。

### 現状の実装

`src/music.ts` の `playHoleOutJingle()`。カップ音の余韻を聞かせるため約1秒遅らせて鳴らす。

浮いて聞こえる理由として、実装上そろっている条件:

- **BGMは同時和音を前へ出さない方針**（ベース + 単音PSG + ノイズ）なのに、
  ジングルだけ4声（C6/9）を2回**同時に**鳴らしている。テクスチャが1箇所だけ違う
- 音色が矩形波 + ノイズヒットで、BGMのトライアングル主体より硬い
- ジングル用のバスを**BGMバスを通さず `context.destination` へ直結**している（`JINGLE_GAIN` = 0.28）。
  シーンの音量調整の外にいる
- 鳴り出しがBGMの拍・小節に同期しておらず、進行中のコードとも無関係に常にC6/9で鳴る
- BGMを 0.78 までしか下げない（`JINGLE_DUCK_RATIO`）ので、別々の曲が重なって聞こえる

### 方向（どれか一つずつ試す。まとめて変えない）

- 音量を下げる（`JINGLE_GAIN`）
- 同時和音をやめ、BGMと同じ単音の動きにする
- 矩形波 + ノイズをやめ、トライアングル中心の柔らかい音にする
- 鳴らす位置をBGMの拍・現在のコードへ合わせる
- ジングルをやめて、カップ音の余韻 + BGMのわずかな持ち上げだけで済ませる案も候補にする

音の判断は実機（スピーカー・イヤホン両方）で行う。数値は `src/config.ts` へ寄せるかも含めて決める。

## 10. PCでギブアップの長押しが成立しない（新規・2026-09-13）

**修正済み・実機確認待ち（PR #94）。**

### 症状

PCでギブアップボタンを長押ししても確定しないことがある。スマートフォンでも起きるかは未確認。

### 原因と修正

- `pointerdown` でタイマーを開始し、`pointerup` / `pointercancel` / `pointerleave` で取り消す
- ボタンは押下中のCSSで3px下へ動くが、マウスのポインターは明示的に捕捉していない
- PCでは、押下中の見た目移動や微小なマウス移動で `pointerleave` が発生し、
  タイマーが取り消される可能性があった
- PR #94で、長押し中のポインターをボタンへ明示的に捕捉した
- ボタン外へ実際に動かした場合は、従来どおり座標判定でキャンセルする

PCで長押しが成立すること、ボタン外へ動かすとキャンセルできること、スマートフォンの
長押しが従来どおり動くことを実機確認する。タッチ操作と長押し時間は変えていない。
