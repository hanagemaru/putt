# パッティングゲーム 試作仕様

スマホ縦画面・ブラウザで動く一人称パッティングゲームのプロトタイプ。
目的は、パッティングの読み・ストローク・転がり・カメラ遷移を実機で検証すること。
グラフィックは簡素でよく、リアルさは見た目より体験を優先する。

---

## 0. 技術スタック

- Vite + TypeScript + three.js
- 物理エンジンは使わず、自前の転がり計算
- パラメータ調整用に `lil-gui`
- three.js 標準の Y-up。グリーンは XZ 平面、高さが Y
- 単位はメートル・秒。チューニング値は `src/config.ts` に集約
- **スマホ縦画面専用。** 横画面では「縦にしてください」のオーバーレイを表示
- `main` への push で GitHub Pages に自動デプロイ

主な構成:

```text
src/
  main.ts                状態機械とゲーム本体の配線
  config.ts              全チューニング定数
  course/                コース定義・サーフェス分類
  green.ts               ハイトマップ生成・表示メッシュ・ホール
  physics.ts             ボールの転がり計算
  swipe-measure.ts       スワイプ計測
  stroke-view.ts         STROKE の2Dオーバーレイ
  cameras.ts             各カメラ姿勢と補間
  smooth-line-overlay.ts 補助線・軌跡の高解像度表示
```

## 1. コース地形

### データ

- 計算領域は幅（X）と長さ（Z）を別々に指定する長方形。正方形も同じ形式で表す
- 物理ハイトマップは約7.8cm、表示メッシュは約15.6cmの目標セル間隔から各軸の解像度を決める
- 既定の検証ページは20m × 20m。現在の試作ホールは16m × 24m
- ガウシアン数個＋緩やかな全体傾斜を合成し、シード指定で再現可能
- 全体傾斜の基準値は 1%
- `sampleHeight(x, z)` / `sampleGradient(x, z)` をバイリニア補間で取得
- 物理と高さ色は同じハイトマップを参照する

### コース外形とサーフェス

`CourseDefinition` をゲーム本体・将来の生成器・検証器で共有する。現在は手作りのパー3を1ホール収録する。

- `bounds`：長方形の計算領域
- `tee` / `cup`：開始位置とカップ位置
- `route`：プレイ可能な芝の中心線。折れ線でドッグレッグを表現
- `greenWidth`：通常芝の幅
- `roughFringe`：通常芝の外側に付けるラフ幅
- `deepRoughFringe`：ラフの外側に付けるセカンドカット幅。ここまではOBにしない
- `waterFringe`：池の岸をラフにする幅
- `hazards`：現在は楕円の池

任意座標は `green / rough / deepRough / water / ob` のいずれかへ分類する。見えるコース外形は長方形そのものではなく、`route` と幅から作る不規則な芝領域になる。

芝は**通常芝 → ラフ → セカンドカット**の順に重くなり、その外側とコース枠の外だけをOBにする。外した一打がすぐOBにならず、重い芝から戻す選択が残ることを優先する。池の岸は芝の途中でも `waterFringe` の幅だけラフにして、水際から直接打つ状況を作らない。

試作ホールの現在値は `greenWidth 4m / roughFringe 1.2m / deepRoughFringe 2.4m / waterFringe 1m`。芝の中心線から片側5.6mまでがプレイ可能で、コース面積に占めるOBは62%から31%へ下がる。

現在の試作ホールは、ティーからカップへの直線が池とOBを横切り、左奥の曲がり角へ刻む安全ルートを持つL字ドッグレッグ。生成器・検証器の前に、外形・視認性・プレイ感を確認するための基準ホールとする。

### 境界の揺らぎ

上の定義をそのまま使うと、芝は折れ線を一定幅で太らせた帯、池は真楕円、岸は均一な輪になり、幾何学模様に見える。
そこで**境界だけを座標のノイズでずらす**。定義（`route` / 幅 / ハザード）は変えない。

- 芝・ラフ・セカンドカットの幅は、位置ごとの倍率で増減する（`CONFIG.course.edgeNoise`）
  - ルートに沿った位置だけでなく左右でも変わるよう、2Dのバリューノイズ（fBm）を使う
  - 折れ線からの距離だけで決めると、帯が左右対称の「太らせた折れ線」のまま残る
  - 帯ごとに別のノイズ列を引くので、3本の縁が平行にならない
- 池の輪郭は、正規化した楕円座標の半径を角度ごとに歪めて真円・真楕円をやめる
  - 波数2〜5の余弦波の重ね合わせ。角度の関数なので輪郭は必ず閉じる
- 岸（`waterFringe`）の幅も同じ作りで角度ごとに変え、広い浅瀬と切り立った岸を作る

守る約束:

- **揺らぎは `CourseDefinition.seed` だけから決まる。** 実行ごとに変わる乱数は使わない
  （デイリーチャレンジは全員が同じコースを遊ぶ）
- **`surfaceAt(course, x, z)` は座標だけで決まる純関数。** 呼ぶ順序・回数で結果が変わらない
  （物理が毎ステップ呼ぶ）。ノイズは列ではなく格子点ハッシュから1点ずつ引く
- 揺らぎの振幅は必ず100%未満。ノイズが [-1, 1] に収まるので、**帯の幅が0以下にならない**
  ＝ 芝が途切れてOBで分断されることがない
- ティーとカップの周囲 `safeRadius` は、最後に必ず通常芝で上書きする

シードは**地形のうねりとコースの外形の両方**を決める。シードを切り替えると外形ごと別のホールになる。
`?seed=12345` を付けるか、`?debug=1` のときだけ出る「シード ⟳」で切り替える（`docs/spec.md` §5）。

### 検証器

`validateCourse(course)` が、コース枠を `CONFIG.course.validationCellSize` の格子で走査して次を返す。
`npm run validate:course` で試験ホールに対して実行できる。

- サーフェス別の面積比
- ティーからカップまで、芝（通常芝・ラフ・セカンドカット）だけを辿って行けるか（4近傍の幅優先探索）
- ティー・カップが通常芝か

`courseSurfaceDigest(course)` は同じ格子のサーフェスを1つのハッシュにまとめる。
同じシードで作り直した定義と突き合わせて、決定論が保たれているかを確かめる。

試験ホール（16m × 24m・格子0.1m）の実測値:

| | 通常芝 | ラフ | セカンドカット | 池 | OB |
| --- | --- | --- | --- | --- | --- |
| 揺らぎなし | 21.3% | 18.3% | 23.8% | 5.3% | 31.2% |
| 揺らぎあり | 21.4% | 21.1% | 23.3% | 5.4% | 28.9% |

縁が外へ膨らむぶんだけ芝側がわずかに増えるが、プレイ可能な範囲の性格は変えていない。
シードを200通り掃引すると（格子0.15m）OBは最小28.5% / 平均31.5% / 最大34.8%で、
どのシードでもティー・カップは通常芝、ティーからカップまで芝が繋がる。

### 現在のアンジュレーション設定

当面は、形状からも傾斜を読みやすくするため以下で固定して実機確認する。

- **物理・高さ色のうねり振幅：±0.20m（強調版）**
- **3D形状のY表示：ハイトマップの1.5倍**
- ボール、カップ、カメラ等の描画位置も1.5倍した見た目の芝面へ合わせる
- 転がり計算と高さ色は1.5倍せず、±0.20mのハイトマップを使う

3D形状1.5倍は現在の**暫定設定**。視認性確認後に再調整する可能性がある。
比較用コード（標準/強調等）は再調整用として内部に残しているが、通常UIからは切り替えない。

### 濃淡

現行の正式方針は **高さベース**。

- コース寸法と目標セル間隔から生成した長方形 `PlaneGeometry` の頂点をハイトマップで変位
- 頂点カラーは **明るい＝高い、暗い＝低い**
- グリーンごとの最小最大では正規化しない。**同じ明るさはどのシードでも同じ高さを意味する絶対スケール**
- `heightStrength = 0.75`
- `heightRange = 0.25m`
- 勾配ベースの濃淡も比較用コードとして残すが、ゲーム本体では `gradientStrength = 0`
- 明暗は基準色を中心に上下へ振る
- `computeVertexNormals()` と DirectionalLight / AmbientLight の陰影も併用

勾配ベースも実機で試したが、「明るい＝高い」が成立せず曲がる向きの読み違いが起きたため、現在は高さベースを採用する。

### ドット感

- `pixel.scale = 3`：1/3解像度のレンダーターゲットへ描画し、`NearestFilter` で引き伸ばす
- グリーンだけでなく、ボール・旗・木も同じ粒度になる
- `pixel.levels = 24`
  - `heightRange / (2 × heightStrength × levels)` より、**1段 ≒ 0.7cm**
- `pixel.colorLevels = 48`（1チャンネルあたり）
- `levels` と `colorLevels` は釣り合わせ、隣接する高さ段が最終色量子化で同色に潰れないようにする
- 2DオーバーレイとHUDは低解像度化しない

### 補助線・軌跡

**高解像度Canvasの滑らかな半透明表示を採用。**
3Dシーンの1/3解像度ドット処理は通さない。

- RESULT軌跡：実際に記録した軌跡点をそのまま結ぶ
  - スプライン補間などで軌跡自体を作り変えない
  - 基準 opacity 55%、線幅2px
- 約0.5mの打ち出し方向ガイド：地面に寝ている線として遠近感を出す
  - 手前ほど太く・濃い
  - 遠端ほど細く・透明
  - 曲がり・傾斜影響を予測するラインではない
  - **ボールより奥にある線なので、ボールに隠れる。** ボールの上へ重ねない
    - Canvasに深度はないので、画面上のボールの円（半径はボールの実寸から求め、`aim.guideBallMaskScale` 倍）を
      クリップから抜いて前後関係を作る

旧ドット版の内部コードは比較を戻す場合のため残しているが、通常UIでは切り替えない。

### ホール・旗竿

- カップ直径 108mm、深さ 100mm
- 表示メッシュに実穴は開けず、芝面上の濃い円＋内壁＋底で穴に見せる
- 旗竿は必ず鉛直。傾きを読む視覚基準にする
- 旗竿は近距離で太く見えすぎず、遠距離でドットにつぶれないよう**表示上だけ距離/FOVに応じて太さを補正**する
  - 基本半径 `0.012m`（12mm）
  - 最大半径 `0.016m`（16mm）
  - 低解像度レンダーターゲット上で最低幅 `1.3px` を目安にする
  - XZ方向だけ連続的に拡大し、高さは変えない
- ADDRESSのカップ後方読み視点だけ、旗竿と旗を opacity `0.18` にして遠いボールを透かして見る
- 他の視点・状態では旗竿と旗を通常の不透明表示へ戻す
- 木も必ず鉛直にする
- 木は**コース枠内のOBエリア**へ置き、地面の高さに立たせる。OBの位置そのものを見て分かるようにする
  - OBエリアが取れないコース（サーフェス分類のない検証ページ）でだけ、従来どおり枠の外の環状に並べる
- 池とOBには高さの濃淡を掛けず単色で塗る。高さを読む対象は芝だけにする
- 池は見た目だけ `0.12m` 下げて、岸との段差で水面が低いと分かるようにする。ハイトマップと物理は変えない

## 2. 物理

固定タイムステップ 1/240 秒。決定論的に保つ。

```text
勾配による加速度: a_slope = -(5/7) * g * ∇h
摩擦による減速:   a_fric  = -MU * normalize(v)
```

- `MU` はスティンプ値から逆算
- 基準はスティンプ 10ft
- ラフ・セカンドカットはプレイ可能で罰打なし。摩擦は通常芝のラフ3.5倍・セカンドカット6.0倍（暫定値）
- 速度が 0.02m/s を下回ったら停止判定。ただし勾配が摩擦を上回る場所では止めない
- 池またはOBに入ったらその場で停止し、そのショットに加えて1罰打を加算して直前のショット位置へ戻す
- 1ホールの上限は `par + 5`。罰打を含めても上限を超えず、到達時点で打ち切る
- 軌跡は一定ステップごとに記録し、RESULTで表示する

### カップ判定

- ボール中心がカップ中心から 54mm 以内に入ったとき判定
- 速度が `1.4m/s` 未満ならカップイン
- それ以上ならリップアウトし、減速して転がり続ける

## 3. 状態機械とカメラ

```text
ADDRESS（読み＋方向調整） → STROKE → FOLLOW → CUP → RESULT → ADDRESS
```

**走行中には俯瞰へ切り替えない。** 分析は停止後だけ。

補間時間のあるカメラ遷移は初期実装より概ね2倍にしている。距離に応じた速度制御にはまだ変更していない。

### ADDRESS（読み＋方向調整）

読みと方向調整は別フェーズに分けない。初期画面は方向調整カメラ。
旧 `BEHIND_BALL` のREAD初期画面はゲームフローでは使わない。

画面下の視点ボタンは **方向調整 / 低い視点 / カップ後方 / 横から** の4つ。
マップは読み視点ではなく一時的な参照画面なので、この列には並べず右下に単独で置く。

#### 操作の約束（全体で統一する）

- **進む＝画面タップ。** ADDRESSの読み4視点はどれからでもタップでSTROKEへ入る。
  RESULTのタップで次打へ進むのも同じ規則
- **切り替え・戻る＝ボタン。** 視点の切り替え、STROKEからADDRESSへ戻る、カップ確認の出入りはボタン
- 左右スワイプは狙い角の調整だけに使う。視点の切り替えには使わない
- マップだけは一時的な参照画面なので、**タップで閉じて直前の視点へ戻る**

視点によってタップが効いたり効かなかったりする状態を作らない。

#### 方向調整（AIM）

- 視点高さ 1.5m、ボール後方 1.5m
- 狙った方向をまっすぐ見る。ROLLは使わない
- 見下ろし角は角度では決めず、ボールから狙い方向へカップまでの距離だけ進んだ芝の上を注視点にする（＝狙った先にピンが見える）
- ただし**足元のボールが画面から外れてはならない**。ボールの接地点が画面高さの
  `address.ballScreenMaxFraction`（0.86）より下へ行きそうなときだけ、足りない分だけ視線を下げる
  - この立ち位置ではボールは視点の約45°下にあり、縦の半画角35°より大きいので、
    長いホールほど視線が水平に近づいて必ず画面から外れる
  - ホールの長さによらずボールの位置は画面内で一定に保たれ、ピンは画角の中に残る
- 左右スワイプで狙い角を変更。角度制限はなく、スワイプを重ねて360°回せる
- 約0.5mの短い打ち出し方向ガイドを表示
- タップでSTROKEへ

#### 低い視点（LOW_LINE）

低い位置からグリーン形状を見ながら、そのまま方向決定にも使う。

- ボールからの距離1m、高さ0.4m
- **左右スワイプでaimを変更可能**
- 約0.5mの打ち出し方向ガイドを表示
- 通常の方向調整と同じく、**ボールを旋回中心としてカメラ位置もaim方向へ回る**
- 常に現在のaimの真後ろ1mから、aim方向を見る
- **タップでそのままSTROKEへ移る**

#### カップ後方（BEHIND_HOLE）

読みのため、ボールとカップを結ぶ線上から低い位置で見る。

- カップ後方距離：1.5m
- 高さ：**0.45m**
- 横ずらし：**0m**
- FOV：**50°**
- 注視点はボールとカップの中間
- この視点の間だけ旗竿・旗を opacity `0.18` にする
- aimは保持するが、この視点では方向調整操作はしない

#### 横から（SIDE_MID）

- ボールとカップの中間の横から見る
- ボールとカップが縦画面の横幅に収まる距離まで自動で引く

#### コースマップ（MAP）

打つ前に「どこへ打てるのか」の全体像を掴むための俯瞰。RESULTの真上俯瞰と同じ見下ろし方で、
枠取りだけを**3点ではなく `course.bounds`（長方形のコース全体）**に変えたもの。

- 右下の単独ボタンで開閉する。**ボールが止まっている間しか見られない**
  - 走行中に俯瞰へ切り替えない原則は変えない
  - 読み視点の列には並べない。目的（コース全体の把握）が読みの4視点と違うため
  - **タップで閉じ、開く前に見ていた読み視点へ戻る**
- 見下ろし角 89.9°、FOV 55°、コース枠に対する余裕 1.08倍
- 見る向きは -Z（ティー側が画面下、カップ側が画面上）。RESULTの yaw 0° と揃える
- 視距離は、**枠の横（X）が収まる距離と縦（Z）が収まる距離の遠いほう**を採る
  - 縦画面は横の画角が狭いので、幅の広いコースは横が決め手になる
  - 16m × 24m・アスペクト0.46（390×844）では視距離 35.9m。X±8.64m / Z±18.70m が画面に入る
- ボール（白）とカップ（赤）の位置は、**斜めの矢印とドット文字のラベル**で示す
  - 実寸のボール（半径21mm）は真上30m超では見えないので、位置そのものを描く必要がある
  - 矢印の先端が、指し示す点にちょうど載る
  - ラベルはゴルフの呼び方に合わせる。ボールは**ティー上なら `TEE`、それ以外は `BALL`**、カップは `CUP`
  - 文字は3×5の大文字ドットフォント。曲線を持たないのでドット絵の画面と揃う
  - 1アートピクセルは画面のドット2個ぶん。390×844では39〜51 × 45px
  - 芝の緑にも池の青にも埋もれないよう、塗りの周り1ドットを暗く縁取る
  - アートは指し示す点の左上へ伸びる。**コースの左半分にある点だけ左右を入れ替え**、
    ラベルが画面外へ出ないようにする（文字自体は鏡像にしない）
  - 視距離が変わっても画面上の大きさは変えない（`sizeAttenuation` なし）
- **曲がりの予測線・推奨ルート・長いラインは描かない。** 出すのはサーフェスの塗り分けと2点の位置だけ
- この視点では方向調整もタップでのSTROKEも行わない。狙い角は保持する

読み視点・マップへ移動しても狙い角は保持する。

### STROKE

- ボール真上、高さ1.5mから真下を見る
- 画面左方向＝狙った方向
- ボールは3Dの実寸表示
- カップと旗竿は強制的に隠さない。**近距離で自然に視野に入る場合だけそのまま見える**
- 木・グリーン外周などの背景物は隠す
- パターヘッド・つま先・ゲート線・スイング軌跡は2Dオーバーレイ
- パターは指を置く前からボール直後に待機する
  - `/swipe-test/` の待機位置36pxは、ボール半径28px＋パター半幅5px＋隙間3px
  - ゲーム本体では3Dボールの見かけ半径を使い、**ボール表面から約3px後ろ**に置く
- **pointerdownだけではパターを動かさない**
  - pointerdown時の待機パター位置を原点にする
  - その後の指の **ΔX / ΔY** だけをパター位置へ反映する
  - 画面上のどこに指を置いても、パターがその指位置へワープしない
- ゲーム本体のフェース表示だけ、計測角の0.6倍・時定数0.10秒で平滑化する
  - 実際の打ち出し方向・計測値にはこの表示補正を掛けない
#### STROKE中のボタン配置

真下視点では、画面のどこが埋まっているかが決まっている。ボタンは**空いている上部へ右揃えで縦に積む**。

| 領域 | 中身 |
|---|---|
| 下中央（下端から18px・高さ30px・幅108〜282px） | つま先の描画 |
| 中央の横帯（y ≒ 画面中央） | ボール・パター・指のドラッグ経路 |
| 中央から左の横帯 | **残り0.5m未満のときカップが出る**（画面左方向＝狙った方向） |
| 上部 | 空き → ボタンを置く |

カップが左へ出るのは、残りが真下視点の視野半幅（高さ1.5m・FOV70°で約0.485m）に収まるときだけ。
390×844では残り0.3mでカップ口が (74, 422) に来る。ここに以前は「カップ確認」列（左中央）が
重なっていた。「方向調整に戻る」（下中央）はつま先の描画とも重なっていた。

- 「方向調整に戻る」ボタンで、打つ前なら狙い角を保持してADDRESSへ戻れる
- 左側の「カップ確認」で、**カメラ位置をボール真上1.5mのまま**狙い方向を見る
  - カップ中心へ固定しない
  - 左右スワイプでそのまま狙いを調整できる
  - 約0.5mの打ち出し方向ガイドを表示
    - **この視点だけ、ガイドをボールから狙い方向へ進めた位置に置く**
    - 真上1.5mから前を見る姿勢では、ボール直後のガイドは視線の70〜89度下にあり、
      縦の半画角35度に入らない（ボール自体もこの視点では画面外）
    - 視線を下げて入れるとカップと旗竿が画面から出るので、線の長さと向きは変えずに位置だけずらす
    - 進める距離は見下ろし角から毎回解き、手前端が画面高さの
      `stroke.cupCheckGuideScreenFraction`（0.92）へ来るようにする。ホールの長さによらず画面上の位置は動かない
  - 30°ROLLは不採用。視野は傾けない
  - 「ストロークに戻る」で真下視点へ戻る
  - 入口は左中央ではなく**右上**（上記の配置表）
- パター反発の「調整」ボタンは**STROKE中だけ表示**する

### FOLLOW

- カメラ位置は固定し、ヨーとピッチでボールを追う
- 打った直後はSTROKEの真下視点を維持
- ボール中心が画面端の約82%へ来た時点で、画面外へ消える前にFOLLOWへ切り替える
- 切替時は現在のボールへ即座に向け、その後は時定数0.25秒で少し遅れて追う
- ボールを常に画面中央へ貼り付けない
- 距離に応じてFOVを 70° → 50°へ緩やかに絞る
- カメラはボールについて平行移動しない

### CUP

- ボールがカップまで**0.5m**を切ったら、カップ後方・芝の高さ付近の定点へカット
- 旗竿でボールが隠れないよう横へ少しずらす
- 最後の曲がりと速度を近距離で見せる
- CUP固定視点でボール中心が画面端の約82%へ来たら、フレームアウト前に**CUPへ入る直前のFOLLOW位置へ戻して追従を再開**する
- 同じ一打ではCUP定点へ再度入らない

### RESULT

- **ボールが完全に停止してから**遷移
- カメラは**ほぼ真上の俯瞰（pitch 89.9°、yaw 0°）**
  - 90°ちょうどの `lookAt` 不安定化を避けるため0.1°だけ逃がす
- 打ち出し位置・停止位置・カップが収まるよう視距離を調整
- ボール軌跡を高解像度の滑らかな半透明黄色線で表示。走行中は表示しない
- 結果テキストを表示
- 次のパットでは停止位置からADDRESSへ戻る

## 4. ストローク（スワイプ入力）

### 4.1 向き

縦画面前提。画面左方向＝狙った方向。

### 4.2 検出

1. 画面に指を置く。この時点ではパターは待機位置から動かない
2. 右へドラッグ＝バックスイング
3. 左へ反転し、フェースがボール右端に触れた瞬間をインパクトとする
4. 指は振り抜きまで画面につけたまま

- ゲーム本体では pointerdown時のパター待機位置を仮想座標の原点とし、指の移動量をそこへ加算する
- インパクトラインは `ballX + ballRadius + putterWidth / 2`
- バックスイング幅は「pointerdownから右へ実際に動いた量」で測る
- `minBackswingPx = 20px`
- 20pxに達するまでアームしない
- 未アームで判定ラインを横切っても終了せず、そのまま引き直せる
- バックスイングのゲート線を表示する

### 4.3 速度

- `pointermove` と `getCoalescedEvents()` をリングバッファへ保存
- ゲーム本体では絶対座標を待機パター基準へ平行移動してから `SwipeMeasure` へ渡す
  - 平行移動なので速度・角度・バックスイング幅は変わらない
- インパクト直前40msのサンプルに最小二乗フィット
- サンプル不足なら窓を広げる
- 判定ラインとの交差時刻は線形補間
- 60/120Hzなど端末差をできるだけ結果へ出さない

### 4.4 パターヘッド

- フェース長 `64px`
- 厚み `10px`
- X/Yとも pointerdown 後の指の移動量をそのまま反映
- pointerdownの絶対位置はパター位置に使わない
- フェースはスイング軌跡と直角
- 表示角は最大35°に制限し、反転させない
- 指を置く前から待機位置に表示
- インパクト後も指の移動量に追従するが、ボールを追い越さないようX位置を頭打ちする

`putterRestOffsetPx = 36` は `/swipe-test/` の基準値。ゲーム本体ではこの値から3pxの隙間を導出し、3Dボールの見かけサイズに合わせる。

### 4.5 芯とミスヒット

```text
offset = ボールY − パター中心Y
```

- `|offset| <= 12px`：減衰なし
- そこからフェース端まで線形に減衰
- 端で `mishitMinGain = 0.55`
- フェース端を超えたら空振り
- 現在は勢いだけを落とし、ミスヒット由来の方向変化は入れない

### 4.6 ボール初速と打ち出し方向

```text
基準ボール初速 [m/s] = swipeVelocityX [px/s] × speedK × ミスヒット減衰
実際のボール初速      = 基準ボール初速 × パター反発倍率
```

- `speedK = 0.00266`
- 当初0.00133から実機調整で2回、各√2倍して現在値にした
- パター反発倍率の既定値は `1.00×`
- 調整UIは `0.50×〜1.50×`、0.05刻み
- **STROKE中だけ**「調整」ボタンを表示し、スライダーを開く
- 倍率はブラウザの `localStorage` に保存し、再読み込み後も維持する
- 将来は練習モードでユーザーが自分のスワイプに合う倍率を決める想定
- `directionSensitivity = 0.4`
- バックスイング幅そのものは結果へ掛けない。打てる所作のゲートとしてのみ使う

### 4.7 `/swipe-test/` のボール反応

`/swipe-test/` の転がるボールは入力確認用の見た目だけの演出。
ゲーム本体の§2の物理とは別物で、ゲームへ持ち込まない。

- `ballPxPerMeter = 1400`
- `ballDecelMs2 = 0.275`
- 0.3m/s程度でも画面外へ抜ける近接視点の演出

### 4.8 指がボールを隠す問題

T4で比較予定。候補:

- (a) ボールを大きめに描く
- (b) ボール周囲にリングを出す
- (c) タッチ位置をボールより手前へオフセットする

ゲーム仕様を変えるため、採用方式は実機比較後に決める。

## 6. ゲーム全体の遊び方・モード

基本ルールは、ホールを順に回って合計打数の少なさを競うストロークプレー。

### 通常ツアー

- コンセプトごとに固定9ホールのコースセットを用意する
- 自分のベストスコアとオンラインランキングを表示する
- 9ホールの暫定構成はパー2×3、パー3×4、パー4×2

### デイリーチャレンジ

- 日付ごとに全ユーザー共通の3ホールを自動生成する
- 暫定構成はパー2・パー3・パー4を1ホールずつ
- 挑戦回数は無制限で、その日のベストスコアをランキングへ登録する
- 3ホール終了後は再挑戦を主導線とし、通常ツアーへの特別な導線は置かない

### 練習

- ランキング対象外で、距離感・傾斜・パター反発調整を自由に試せる

### 広告

- 3ホール終了時に全画面広告を表示する
- ラウンド途中で離脱し、別のニューゲームを始めるときは開始前に全画面広告を表示する
- 広告直後や、まだ1打もしていないラウンドの切替で二重・不要表示しない

ランキング、広告、モード遷移、日次生成は未実装。現在はそれらに先立つ長方形コース・サーフェス・罰打ルールを試作している。

## 7. 実装しないこと

- 長いライン予測
- 傾斜を含む曲がり予測
- STROKE中のホールを距離に関係なく強制表示・強制非表示する処理
- ボール走行中の俯瞰
- 凝ったテクスチャ・シェーダー・モデル
- サウンド（現段階）
- コースデータの外部読み込み（現段階）

ADDRESS方向調整・LOW_LINE・STROKEカップ確認の約0.5m直線は、ライン予測ではなく打ち出し方向の表示として例外的に使用する。

## 8. 実機確認の基準

1. 同じスワイプで距離が再現性をもって出るか
2. 縦画面の横幅でバックスイングと強いストロークが両立するか
3. 芯を外した結果が自分のミスとして納得できるか
4. ADDRESSの濃淡・読み視点で高低差を読めるか
5. FOLLOWで曲がりと強さが自然に見えるか
6. RESULTの真上俯瞰で、軌跡と高さの濃淡を答え合わせできるか
7. 旗竿が近距離で太すぎず、遠距離でも消えないか
8. STROKE開始時のパターがボール直後の自然な位置に見えるか
9. LOW_LINEでボール中心を軸にカメラが自然に回り、そのままタップでSTROKEへ進めるか
10. カップ後方0.45m視点で、旗を透かしてボールとグリーン形状を読みやすいか
11. 先細り・フェードする短いガイドが地面に寝た線として見えるか。ガイドがボールに隠れて見えるか
    - カップ確認では、前方へずらしたガイドが狙い方向の目印として読めるか
12. 強調±0.20m＋形状1.5倍で、色と形状の両方からアンジュレーションを把握しやすいか
13. pointerdown時にパターが動かず、指のΔX/ΔYだけに自然に同期するか
14. パター反発倍率を変えたとき、自分のスワイプ感覚に合わせやすいか
15. 16m × 24mの長方形上で、L字の通常芝・ラフ・セカンドカット・池・OBを見分けられるか
16. 池とOBで1罰打が加わり、直前位置へ戻るか。`par + 5`を超えないか
17. 狙いを360°回して、ドッグレッグの安全ルートを選べるか
18. 芝を外してもセカンドカットで止まり、OBになる頻度が妥当か
19. 長いホールでも方向調整画面にボールが入り、見下ろし角が窮屈でないか
19. ラフ3.5倍・セカンドカット6.0倍の重さが、罰を受けつつ戻せる程度か
20. 池が一段下がって見え、岸のラフと池・OBの単色が芝の濃淡と区別できるか
21. OBエリアに立つ木が、狙いどころの目印として機能するか（視界を邪魔しすぎないか）
22. コースマップで16m × 24mの全体が縦画面に収まり、どこへ打てるのかを掴めるか
23. マップの矢印とラベル（TEE / BALL / CUP）が読めるか。大きさと位置がちょうどよいか
24. 芝・ラフ・セカンドカットの縁と池の輪郭が、幾何学模様ではなく自然な形に見えるか。
    揺らぎが強すぎて狙いどころが読めなくなっていないか

操作感・見た目の評価は実機で行う。AIは実機で「良くなった」と自己判断しない。
