# コース生成器v2 設計案（**提案。まだ合意していない**）

作成: 2026-09-14 / 状態: **設計として合意済み（2026-09-14）。実装はこれから**

現行の生成器（`src/course/course-generate.ts`）を**v1として一切変えずに残し**、v2を別ファイルとして追加する提案。
v1で作った既存3コース・週替わりチャレンジv1・過去の検証結果はそのまま再現できる。
v1のコースとv2のコースは**両方ともツアーとして並べられる**ようにする。

背景と直したい症状は `docs/PLAYTEST_BACKLOG.md` §1、現行の仕様は `docs/spec.md` §1。

## 1. なぜv1では直せないか

2026-09-13 にシード1〜1000を走査して分かった、選定側では回避できない制約。

- **ルートが3〜4点の折れ線**。`straight` は中間点を横へずらした弓なり、`dogleg` は1回、
  `doubleDogleg` は2回、進行方向を折る。曲がりは常に「角」であって「カーブ」ではない
- **`cornerAngle` が難易度に直結している。** hard は 60〜105°。
  つまり **hardのホールは60°より緩く曲がれない**。「長くて少しだけ曲がるホール」が作れない
- 折れ角と難易度が一体なので、**難しさを角度以外から作れない**
- 「むずかしい」PAR4のルート全長は実測 **20.1〜22.0m しかない**。
  9ホール中5本がこのPAR4なので、距離ではホールを描き分けられない

## 2. v2の考え方

**`CourseDefinition` の形は変えない。** 変えるのは「ルートの折れ線をどう作るか」と
「難易度をどう作るか」だけ。`surfaceAt` / ハイトマップ / 物理 / 検証器 / コースマップ /
セーブ形式は現状のまま動く。

### 2-1. ルートを曲線から作る

制御点を2〜4点だけ置き、**Catmull-Rom（またはB-spline）を一定の弧長間隔でサンプリングして
折れ線に落とす**。折れ線という器はそのまま、点数だけを増やす。

- 型は3種の離散値をやめ、連続量で表す
  - `gentleCurve`: 全体が1本の緩い弧（v1のストレート＋浅いドッグレッグを吸収）
  - `sweepingDogleg`: 向きの変化は1回だが、長い区間へ配分して「角」を作らない
  - `serpentine`: 逆向きの曲がりを連続させる（v1のS字を吸収）
- 効かせるパラメータを**折れ角から曲率へ**置き換える
  - `totalTurn` [度]: ティーからカップまでの**総回頭角**。「どれだけ曲がるホールか」
  - `minTurnRadius` [m]: **最小曲率半径の下限**。「どれだけ急に曲がってよいか」
  - `turnSpread`: 回頭をルートのどれだけの区間に配分するか（大きいほど雄大なカーブ）

この分離が要点で、**「大きく曲がる」と「角が鋭い」を別々に指定できる**ようになる。
v1では同じ1つの数字だった。

`minTurnRadius` は芝幅と結びつける（例: 芝幅の3倍以上）。
芝幅より小さい半径で曲げると、内側の芝が自分自身と重なって曲がりが消える。

### 2-2. 難易度を角度以外から作る

v1の hard = 長い + 芝が狭い + 角が鋭い。v2では次を足す。

1. **池を「近道の内側」へ置く。** 現在は ティー→カップ直線上の点から乱数方向へずらしているだけ。
   v2ではカーブの**内側**に置き、「回り込めば安全・カットすれば池越え」を成立させる
2. **区間ごとの難所。** 落としどころ（1打目が止まる帯）だけラフを厚くする
3. **上りと下りの配分。** 地形の性格（`terrain`）はカップ基準で置いているので、
   ルートの向きと組み合わせて「打ち上げのカーブ」「打ち下ろしのカーブ」を作り分ける

**段階2（v2の最初の版には入れない）**として検討するもの。`CourseDefinition` の拡張が要るため。

- 芝幅をルートに沿って変える（`greenWidth` をスカラーから幅プロファイルへ）
- カップをルート終端からずらす（池際・段上など）

### 2-3. ハザードを増やす（**4種とも採用決定・2026-09-14**）

現在のハザードは**楕円の池1種類だけ**（角度調和で輪郭を歪ませてある）。
増やす前に、このゲーム固有の制約を先に置く。

#### 前提: 球は転がるだけで、飛ばない

- **水は越えられない。** だから水は芝の通り道を塞げない。必ず脇へ置く
  （v1も `hazardRouteClearance` で通り道を空けている）
- **砂と地形は越えられる。** だから**線の上に置ける**。
  正面に置いて「強く越えるか、避けて回すか」を作れるのは砂と地形だけ
- 立体の障害物（木・岩）は当たり判定＝反射が要る。物理エンジンを使わない前提と相性が悪い

この違いが、そのままハザードの役割分担になる。
**水＝罰打 / 砂＝打数のロス / 地形＝読みの難しさ。**

#### 提案するハザード

| # | ハザード | 罰打 | 線上に置けるか | 新サーフェス | 実装コスト |
|---|---|---|---|---|---|
| 1 | クリーク（細長い水） | あり | 置けない | 不要（水のまま） | 中 |
| 2 | バンカー（砂） | なし | **置ける** | **必要** | 中〜大 |
| 3 | マウンド・リッジ・窪地 | なし | **置ける** | 不要 | 小 |
| 4 | 深いラフの島 | なし | 置ける | 不要 | 極小 |

**1. クリーク（細長い水）**
池の型を楕円だけでなく「折れ線＋幅」も持てるようにする。
カーブの**内側**へ沿わせると、「回り込めば安全・カットすれば水」がはっきり出る。
罰打・見た目・岸（`waterFringe`）の仕組みは既存の水をそのまま使える。
`EllipseHazard` を union にして、`isInsideWater` に線分距離の判定を足すだけ。

**2. バンカー（砂）**
罰打はなし。摩擦がセカンドカットよりさらに高く、**止まる**。
水と違って越えられるので、**直線ホールの正面に置ける唯一の罰則的ハザード**になる。
「強く打って越えるか、避けて遠回りするか」を、曲がり角を大きくせずに作れる。

- **縁を立てない。平らな砂だけにする。** 壁を作ると出られなくなる（詰み）
- 高さの濃淡は掛ける（池・OBと違い、地形を読ませたいため）
- `SurfaceType` の追加なので、色・摩擦・検証器・`check:stuck`・走査スクリプトへ波及する
- 上り斜面の砂は「打っても出ない」になりうるので、`check:stuck` の合格条件に必ず入れる

**3. マウンド・リッジ・窪地（高さのハザード）**
ハイトマップへ局所的な盛り上がり／尾根／窪みを足すだけ。
**新しいサーフェスも罰打も要らない**ので、いちばん安く効く。

- ルートを横切る尾根: 「越えるには強く、越えすぎると奥へこぼれる」
- 窪地: 止まると上りが残る
- 注意: 勾配が摩擦を上回る場所では止まらない仕様なので、急にしすぎると転がり続ける。
  勾配の上限を `CONFIG.course.generatorV2` に置く

**4. 深いラフの島**
既存のセカンドカットを、帯としてではなく**塊**としてルートの中や脇に置く。
「近道側だけ重い」を極小のコストで作れる。

#### 採らないほうがよいと考えるもの

- **木・岩などの立体障害物**: 反射を物理へ足すことになり、決定論とリプレイの前提が重くなる。
  「物理エンジンは使わない」「グラフィックは簡素でよい」とも合わない。
  木は今までどおりOB側の飾りのままにする
- **崖・落下**: 高さで作れるが、落ちた先が到達不能になると詰みになる。OBで代用するほうが安全

#### 入れる順（4種とも入れる。順番だけ分ける）

1. **3（高さのハザード）と 4（ラフの島）を v2 の最初の版へ。**
   新サーフェス不要・罰打不要で波及が小さいので、ルート曲線化と同じタスクに入れられる
2. **1（クリーク）をその次。** 既存の水の仕組みに乗るので、ハザードの型を union にするだけ
3. **2（バンカー）は独立した1タスクにする。** `SurfaceType` の追加は波及が広く、
   詰み検証もやり直しになるため、v2のルート曲線化とは混ぜない

#### バンカーを足すときに触るところ（実測で洗い出した）

`deepRough` がどこに出てくるかを数えた結果。新しいサーフェスを1つ足すと、
**最低でもこれだけの場所に分岐が増える。**

| ファイル | 何を足すか |
|---|---|
| `src/course/course-types.ts` | `SurfaceType` に `bunker` を足す |
| `src/course/course-map.ts` | `surfaceAt` の判定。バンカーの領域を池と同じ作りで持つ |
| `src/physics.ts` | `frictionMultiplier` に分岐を1本 |
| `src/config.ts` | 色・摩擦倍率・バンカーの寸法（`course` 配下と `physics` 配下） |
| `src/green.ts` | 頂点色の基準色。**高さの濃淡は掛ける**（池・OBと違い地形を読ませる） |
| `src/course/course-validate.ts` | 面積比の集計とラベル（5か所） |
| `scripts/check-stuck.ts` | **止まれるマスに含める**（6か所）。詰み検証をやり直す |
| `scripts/validate-course.ts` / `scripts/survey-holes.ts` | 集計とラベル |
| `src/entry.ts` | 色の一覧のコメント |

設計上の約束もあわせて決めておく。

- **罰打なし。** 水・OBと違い、止まっても打ち直しではなく、そこから打つ
- **縁を立てない。平らな砂だけ。** 壁を作ると出られなくなる（詰み）
- 摩擦はセカンドカット（`deepRoughFrictionMultiplier: 6`）よりさらに高くする
- **上り斜面の砂を作らない。** 勾配の上限を設け、`check:stuck` の合格条件へ入れる

### 2-4. 9ホールを組む指標

2026-09-13 の風の丘の選び直しで使った条件を、走査スクリプト側の再利用可能な選定条件にする。

- 隣り合うホールで**形**と**地形**を重複させない
- 地形は2つ飛ばしでも重複させない
- 最終ホールをラウンドの最長にする
- PAR3×2・PAR4×5・PAR5×2（合計36）、PAR4は5地形を1本ずつ
- 直線とカーブが交互になるようにする

## 3. v1とv2を共存させる

- `src/course/course-generate.ts`（v1）は**触らない**
- `src/course/course-generate-v2.ts` を追加し、`generateCourseV2(seed, options)` を公開する
- 調整値は `CONFIG.course.generatorV2` に置く（`CONFIG.course.generator` はv1のまま）
- `TourDefinition` に `generator?: 'v1' | 'v2'` を足す。**省略時は 'v1'** なので既存3セットは無変更
- コース選択画面には、v1のコースとv2のコースを**同じ一覧に並べる**
- 週替わりチャレンジは当面v1のまま（`CHALLENGE_SEED_POOLS_V1` は触らない）。
  v2へ移すなら別プールをv2として足す

  **v2のコースを足しても既存の保存は消えない**

## 4. 性能（実測済み・v2は成立する）

`surfaceAt` は 1点ごとに `distanceToRoute` を呼び、これがルートの点数に比例する。
曲線化は点数を増やすので、ここが唯一の性能リスク。**実測した**（seed 728・枠22.5×24m）。

| ルート点数 | surfaceAt 1回 | 3点比 |
|---:|---:|---:|
| 3（v1の現状） | 0.70μs | 1.00 |
| 9 | 0.85μs | 1.21 |
| 17 | 1.11μs | 1.59 |
| 33 | 1.69μs | 2.41 |
| 49 | 2.17μs | 3.10 |

点数に正比例はしない（池の判定と縁のノイズが固定費として乗るため）。
1m間隔で刻めば25mのホールで25点前後。この範囲なら:

- コースメッシュの色付け（約2.2万頂点）: 15ms → 37ms。ホール切り替え時の1回だけ
- 生成時の検証（0.2m格子・平均2.06回試行）: 19ms → 46ms
- 物理（1ステップ2回・240Hz）: 0.34ms/秒 → 0.8ms/秒

実機はこの数倍遅いが、いずれも1ホールにつき1回か、毎秒1ms未満。**そのまま進めてよい。**
足りなければ、池の形と同じ `WeakMap` キャッシュの作りで
**ルートの線分をコースごとに格子索引化**すれば点数への依存を消せる。

## 5. 比較方法（v2を採るかどうかの決め方）

### 機械で見る（合格条件）

- fallback 0 本
- ティー側から到達できない芝の島 0（v1はシード1〜1000で15本・1.5%）
- `npm run check:stuck` で詰み0・カップイン可
- OB面積比が既存の受け入れ範囲（18〜45%）に収まる
- **最小曲率半径が下限以上**（v2で新たに測る）
- 総回頭角の分布が90°前後に固まっていない（v1の症状の再発チェック）

### 人が見る（ここで採否を決める）

- **基準ホールを壊さない。** 曲がりの森H8=649、水鏡の庭H1=394 / H4=235 / H7=411 / H8=421 は
  v1のまま残るので、**v1のコースとv2のコースを同じ画面から選んで交互に遊んで比べる**
- 見るところ
  1. 曲がりが「折れ」ではなく「カーブ」に見えるか
  2. S字が自然な蛇行に見えるか
  3. 難しさが角度以外（芝幅・池・傾斜・近道の選択）から来ていると感じるか
  4. v1のコースと並べたとき、v2のほうが面白いか。**同等なら採らない**

### 進め方

1. v2のルート生成だけ作る。ツアー化はまだしない
2. シードを走査して、総回頭角・最小曲率半径・遠回り率の分布を見る
3. v2で3コース分の候補を組む（§2-3の指標を使う）
4. 既存3コースと並べて実機比較
5. 良ければv2のコースを**追加**する。v1のコースは残す
